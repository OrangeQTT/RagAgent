# 知识库入库 SOP

千言的知识库是 RAG 检索链路的数据源，有三条工程约束是你无法从内容本身推断出来的：

1. **切分器只认 `###`**：入库文档按三级标题切块，一个 `###` 到下一个 `###` 之间就是一个检索单元。正文里任何一行以 `###` 开头，都会把这条知识劈成两半。
2. **一个块就是一次检索命中的全部上下文**：一块里塞了两件事，用户问其中一件时，另一件就是噪声。
3. **BM25 靠字面 token 命中**：把「它」「这个版本」这类代词换成完整实体名，召回率明显不同。

所以入库不是"把文字追加到文件末尾"，而是一次要满足上述约束的规范化操作。

## 执行步骤

### 第 1 步：查重

调用 `searchKnowledge`，参数用这条知识的**核心问题**，不要把用户整段原话丢进去。

| 返回情况 | 动作 |
|---|---|
| 为空，或讲的是别的事 | 走第 2 步，新增 |
| 已有条目和用户说的完全一致 | 告诉用户"已有这条"并贴出原文，**不要重复入库**，结束 |
| 已有条目问的是同一件事、但答案不同 | **停下来问用户**是覆盖还是两条都留，不要自己决定 |

### 第 2 步：规范化

**question**：完整、能独立看懂的疑问句；主语写全（写「千言项目用的向量数据库是什么」，不要写「用的什么数据库」）；单行；不要带 `### Q.` 前缀，工具会自己加。

**answer**：第一句就把结论说完；代词换成完整实体名；**只讲一件事**——用户一口气说了三件事就调三次工具；不要带 `A：` 前缀；任何一行都不能以 `###` 开头，要提到三级标题就写成「三个井号」。

**fileName**：用户指定了就用用户的，没指定就传 `Test.md`。

### 第 3 步：写入并回报

调用 `addKnowledgeToRag(question, answer, fileName)`。

返回的是失败信息时**不要原样重试**，按提示改完再调一次。

成功后向用户回报三件事：入库了几条、每条规范化之后的**问题原文**（让用户能核对你有没有改变原意）、写进了哪个文件。

## 一个例子

用户说：「那个 rerank 用的模型记一下，是 qwen3-rerank，阈值我们设的 0.2」

- question：`千言项目的 rerank 重排序用的是哪个模型？相关性阈值设成了多少？`
- answer：`千言使用百炼平台的 qwen3-rerank 作为重排序模型，通过 langchain4j 的 QwenScoringModel 接入；相关性阈值 rerank-min-score 配置为 0.2，低于该分数的候选片段会被丢弃。`

注意这一步做了什么：把「那个 rerank」补成完整主语、把「我们设的 0.2」补成「相关性阈值 rerank-min-score 配置为 0.2」、把 `qwen3-rerank` 这个字面串完整保留——都是为了让 BM25 那一路能命中。

## 不适用（正常回答即可，不要用本技能）

- 用户只是在提问，哪怕问的正是知识库里的内容
- 用户让你"记住"的是本次会话的临时偏好（比如「接下来都用英文回答」）——那是会话记忆的事，不该进知识库
